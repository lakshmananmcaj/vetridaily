VetriDaily · Build step 1

Festival Feature Spec

The festival screens don't sell anything by themselves. They earn by creating eighteen high-intent moments a year where you have a reason to reach a devotee — and something relevant to offer at that exact moment.

The sleeper field

StartingTime/EndTime is the one to build around. Devotees re-check auspicious timing repeatedly on the day itself, which turns a single festival into several app opens rather than one.

Placement rules

  • One card, below the festival body copy. Never an interstitial, never above the content.
  • Copy names the benefit, not the format — "Plan your Palani trip" beats "Buy PDF (2.4 MB)".
  • Suppress entirely for users who already own the product.
  • Be careful on Amavasai — it's reflective, not celebratory. Test that placement before shipping it.

The evening-before push matters more than anything on the screen itself. It's the difference between a festival feature people happen to discover and one that actually reaches them.

Streams B–E

Four more ways the same screens earn

Stream B

Festival audio packs

Your daily audio pipeline already generates Tamil devotional audio. A festival pack is the same machinery pointed at a themed script. Skanda Sashti is the obvious first product — six days, six audios, sold as one pack, and you already have sashti-audio.m4a in the rasi repo. Release it day by day so buyers open the app six mornings running. This is the only genuinely new content in the plan, and it's one script per day for six days.

Stream C

The Murugan temple directory

Nearly free, and you may not realise you have it:

GET /api/temples?deity=Murugan&page=1&pageSize=20
GET /api/temples?deity=Murugan&city=Palani
GET /api/temples/{slug}

TempleListDto carries NameTamil, DeityTamil, Location, City, ImageURL. An Arupadai Veedu screen — the six sacred abodes — is a headline feature that costs one query parameter. Link each festival to its temples, and put the Temple Travel Guide card where intent is highest in the entire app.

Stream D

Video feed into your channel

VideoListDto already carries VideoURL, CategoryName, Views, Likes and — notably — IsPremium. You have a premium-video flag built and unused. Free videos open with vnd.youtube: so the view lands in the signed-in native app and counts toward watch time; premium ones sit behind the same Play Billing entitlement as the PDFs.

Stream E

Festival sponsorship from local business

You have DirectoryController with categories and featured — a business directory. Tamil festivals are shopping seasons; silk shops, jewellers and travel operators all spend around Thai Poosam. A "featured near you" slot on a festival or temple page beats AdMob rates because it's targeted by intent, region and date. Honest caveat: this needs real install numbers before anyone pays. Build the slot now, sell it in year two.

Section 3

What this actually earns

Assumptions stated so you can argue with them: 15–25% push open rate (opted-in devotees run high), ~3% conversion on major festivals and ~1% on monthly observances, ₹149 average price, Play takes 15%, 18 revenue events a year.

Read this honestly

At 1,000 installs this is roughly ₹400 a month — not a business. The numbers only get interesting past about 20,000 installs. That isn't an argument against building it, it's the argument for building it first: it scales linearly with installs while costing nothing per user, the backend already exists, and it's the retention engine that grows installs in the first place. The real value is eighteen reasons a year to reopen the app. Direct sales are the bonus on top.

Section 4

Build checklist

Client
  • Second Retrofit interface for api.informationneeds.com — separate base URL from Supabase
  • FestivalListDto / FestivalDetailDto / TempleListDto data classes
  • Home card — next 3 upcoming festivals
  • Festival list screen with month + year toggle
  • Festival detail — Tamil name first, FeaturedImage hero, muhurat window, body
  • Arupadai Veedu screen — ?deity=Murugan
  • Share sheet reuses the existing share/ package with FeaturedImage
  • 24h disk cache — festivals change rarely, and it makes the app work offline
Monetization
  • Play Billing Library, one-time INAPP products
  • slug → product id config table
  • slug → video id config table
  • Server-side purchase token verification before PDF delivery
  • Entitlement check honouring IsPremium on videos
Retention
  • Festival reminder scheduling via the existing WorkManager setup
  • Server push the evening before, via PushNotificationService
  • Per-festival opt-out so reminders never feel like spam
Ship order within this feature

Home card → detail screen → list/calendar → temples → billing. The home card alone, showing the next festival with its Tamil name and date, is worth shipping before any of the rest exists.
